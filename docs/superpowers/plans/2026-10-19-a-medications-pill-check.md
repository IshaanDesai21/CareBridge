# Plan A — Structured Medications & Pill Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bottle scans save structured dosing (form, strength, pills-per-dose range, doses/day, as-needed). Caregivers verify a dose with one photo, using an on-device Create ML detector for four drugs, or log it manually. A backend rule engine decides pass/fail, logs doses, and records and resolves flags.

**Architecture:** iOS runs `PillDetector.mlmodel` through Vision and posts raw detections. The backend (`services/doseRules.js`, pure) applies every pass/fail rule against the medication list and the day's dose totals, then persists `pill_checks` + `dose_logs`. A Python/Swift pipeline under `ml/pill-detector/` builds the model and a pill-appearance catalog from the NIH C3PI archive.

**Tech Stack:** Node 20 ESM + Express + pg (via `db.js` sqlite-shaped wrapper) + vitest; SwiftUI iOS 17, Vision, Core ML; Python 3 (Pillow, NumPy, requests) for data prep; Create ML (`CreateML.MLObjectDetector`) via a macOS Swift script.

**Spec:** `docs/superpowers/specs/2026-10-19-pill-check-calendar-messages-design.md`

## Global Constraints

- Four target classes, exact labels: `benzonatate`, `phenazopyridine`, `atorvastatin`, `lisinopril`; a fifth class `other` for distractor pills.
- Exclude combination products from targets: any name containing `HYDROCHLOROTHIAZIDE`, `AMLODIPINE`, `CLAVULAN`, or `/`/` and ` between two drug names.
- Daily maximum = `pills_per_dose_max × doses_per_day`.
- Correction window: **30 minutes**. A pass clears a failure only if it contains every `medicationId` named in that failure's problems. Failures with no medication-specific problems are cleared by any pass in the window.
- Photos are never uploaded or stored.
- Only `caregiver`/`organization` roles may create pill checks or manual dose logs.
- Dates are client `local_date` strings `YYYY-MM-DD` (device time zone).
- Every new `APIService` method has an `isDemoMode` branch returning canned data.
- Backend schema changes go in `initializeTables()` in `backend/src/database/db.js` (`CREATE TABLE IF NOT EXISTS` / `ALTER TABLE … ADD COLUMN IF NOT EXISTS`). No migration tool.
- The iOS project uses synchronized folders. New files under `ios/CareBridge/` are picked up automatically; don't edit `project.pbxproj`.
- There is no iOS unit-test target (files in `ios/CareBridge/Tests/` are not compiled). iOS tasks verify with a simulator build plus a demo-mode run.
- Model acceptance bar: ≥ 95% per-class count accuracy on held-out composites; ≥ 90% top-1 on real `C3PI_Test` photos (held-out NDCs); ≥ 90% distractor rejection; < 1 s inference. Report actual numbers if not met.

**iOS build command** (used by every iOS verification step):

```bash
cd ios && xcodebuild -project CareBridge.xcodeproj -scheme CareBridge -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO 2>&1 | grep -E "error:|BUILD"
```
Expected: `** BUILD SUCCEEDED **`, no `error:` lines.

## Review Focus

1. **Two active medications map to the same class** (for example, old and new lisinopril strengths both active). Expect fail `duplicate_medication` naming both, never an arbitrary pick. Test in Task 3.
2. **Strength strings in different spellings** ("10mg", "10 MG", "10 mg tablet"). Expect them to compare equal after normalization. Test in Task 3.
3. **A medication on the list but missing from the photo has incomplete setup.** Expect no failure; only medications present in the photo are required to be set up. Test in Task 3.
4. **A failure followed by a pass after exactly 30 minutes or later.** Expect the flag to stay (window is `< 30 min`). Test in Task 3.
5. **A patient with no active medications photographs pills.** Expect every pill to be `not_on_list`, with a clear message, not a 500. Test in Task 3.

### Task 3: Dose rule engine (pure)

**Files:**
- Create: `backend/src/services/doseRules.js`, `backend/src/data/pillCatalog.json` (seed)
- Test: `backend/tests/doseRules.test.js`

**Interfaces:**
- Produces (all exported from `doseRules.js`):
  - `TARGET_CLASSES = ['benzonatate','phenazopyridine','atorvastatin','lisinopril']`
  - `CLASS_FORM = { benzonatate:'capsule', phenazopyridine:'tablet', atorvastatin:'tablet', lisinopril:'tablet' }`
  - `CONFIDENCE_THRESHOLD`: `Number(process.env.PILL_CONFIDENCE_THRESHOLD ?? 0.6)`
  - `CORRECTION_WINDOW_MS = 30 * 60 * 1000`
  - `normalizeStrength(s: string|null) → string|null`: lowercases, collapses `"10mg"`, `"10 MG"`, `"10 mg tablet"` → `"10 mg"`; supports `mg`, `mcg`, `g`; returns the first number+unit match.
  - `drugClassFor(medicationName: string) → string|null`: the target class whose name appears as a word in the lowercased name.
  - `evaluatePillCheck({ detections, medications, todayTotals, catalog, threshold? }) → { status:'pass'|'fail', problems: Problem[], doses: Dose[] }`
    - `detections: Array<{ label: string, confidence: number, imprint?: string|null }>`
    - `medications`: active rows from DB (snake_case columns)
    - `todayTotals: Record<medicationId, pillsAlreadyLoggedToday>`
    - `catalog: Array<{ imprint, drug, strength, form }>`
  - `evaluateManualDose({ medication, pillCount, todayTotal }) → { status, problems }` (count range + daily max + setup checks only)
  - `resolvableFailureIds({ failures, passedMedicationIds, now }) → number[]`, where `failures: Array<{ id, created_at, problems: Problem[] }>`
  - `Problem = { code, message, medicationId?, label?, expected?, counted? }`, with `code ∈ no_pills | unrecognized | not_on_list | duplicate_medication | setup_incomplete | wrong_form | wrong_strength | count_mismatch | over_daily_max`
  - `Dose = { medicationId, pillCount, strengthVerified: boolean }` (only populated when `status === 'pass'`)

**Rule order** (collect *all* problems, don't stop at the first):
1. No detections → `no_pills`.
2. Each detection with `confidence < threshold` or `label === 'other'` or label not in `TARGET_CLASSES` counts toward one `unrecognized` problem (`counted` = n).
3. Group the remaining detections by label. For each label:
   - Find active meds with `drugClassFor(name) === label`.
   - 0 matches → `not_on_list`.
   - More than 1 match → `duplicate_medication`.
   - Otherwise, with `med`:
     - `setup_incomplete` if any of `form`, `pills_per_dose_min`, `pills_per_dose_max`, `doses_per_day` is null.
     - Else `wrong_form` if `med.form !== CLASS_FORM[label]`.
     - For each detection with an imprint found in `catalog` (case-insensitive, spaces/`;` stripped): if `entry.drug !== label` → add it to `unrecognized`; if `normalizeStrength(entry.strength) !== normalizeStrength(med.strength)` → `wrong_strength`.
     - `count_mismatch` if count is outside `[min, max]`.
     - `over_daily_max` if `todayTotals[med.id] + count > max * doses_per_day`.
     - `strengthVerified` is true only if every detection of this label had a matching imprint.

**Message copy** (exact; `<Name>` is `med.name`, `<label>` is title-cased):
- `no_pills`: `"No pills found in the photo. Spread the pills out on a flat surface and try again."`
- `unrecognized`: `"Couldn't recognize <n> pill(s). Check them by hand before giving."`
- `not_on_list`: `"<label> isn't on this patient's medication list."`
- `duplicate_medication`: `"<label> is listed more than once. Remove the old entry before checking."`
- `setup_incomplete`: `"Finish setting up <Name>: pills per dose and times per day are needed."`
- `wrong_form`: `"<Name> should be a <form>, but a <detected form> was found."`
- `wrong_strength`: `"<Name> should be <strength>, but this pill looks like <detected strength>."`
- `count_mismatch`: `"Expected <min> <Name>, counted <n>."` (or `"Expected <min>–<max> <Name>, counted <n>."` when min ≠ max)
- `over_daily_max`: `"This would be <total> <Name> today — more than the daily maximum of <max>."`

### Task 6: ML data — fetch C3PI, build manifest and appearance catalog

**Files:** create in `ml/pill-detector/`: `requirements.txt` (`pillow`, `numpy`, `requests`), `.gitignore` (`data/`, `.venv/`, `out/`), `fetch_c3pi.py`, `build_catalog.py`, `README.md`.

**Interfaces:**
- Produces:
  - `data/manifest.csv` with columns `ndc11,class,layout,local_path,imprint,color,shape,name`
  - `pill_catalog.json` (committed), copied to `backend/src/data/pillCatalog.json`: `[{ "imprint": "PA83", "drug": "benzonatate", "strength": "200 mg", "form": "capsule", "color": "YELLOW", "shape": "OVAL", "ndc11": "00555188302" }]`

**Facts the scripts rely on** (verified 2026-10-19):
- Index: `https://data.lhncbc.nlm.nih.gov/public/Pills/directory_of_images.txt`. Pipe-separated `ndc11|part|relative_path|layout|name`.
- Images: `https://data.lhncbc.nlm.nih.gov/public/Pills/<relative_path>`
- Per-disc metadata: `https://data.lhncbc.nlm.nih.gov/public/Pills/ALLXML/<PillProjectDiscN>.xml`. `<Image>` elements carry `NDC11`, `File/Name`, `Imprint` (`;`-separated sides), `Color`, `Shape`, `Layout` or `Class`.
- Strength: `https://rxnav.nlm.nih.gov/REST/ndcstatus.json?ndc=<ndc11>` → `ndcStatus.conceptName` (for example `"benzonatate 200 MG Oral Capsule"`).
- `MC_C3PI_REFERENCE_SEG_V1.6` PNGs are 16-bit RGBA cut-outs (alpha = pill mask). `C3PI_Test` are JPG phone photos.

**Script behavior:**
- `fetch_c3pi.py [--distractors N]`:
  - Selects target rows by drug name, excluding combos per Global Constraints.
  - Selects distractor rows: default 60 NDCs from other drugs, round-robin over XML color/shape groups, prioritizing `WHITE|PINK|YELLOW|PEACH` × `ROUND|OVAL|CAPSULE`.
  - Downloads only layouts `MC_C3PI_REFERENCE_SEG_V1.6` and `C3PI_Test` (JPG), with resume and skip-if-exists.
  - Writes the manifest.
- `build_catalog.py`: for each target NDC, writes one catalog row per imprint side, with strength parsed from the RxNav `conceptName`.
